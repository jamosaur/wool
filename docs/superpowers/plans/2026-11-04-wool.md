# wool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Herdr app mod that runs a repo's setup steps in every fresh git worktree space and lays out plain-shell worktree spaces from committed `.herdr/*.yml.dist` files with personal `.yml` overrides.

**Architecture:** All decisions are pure ES modules under `mods/wool/lib/` (YAML subset reader, schema validation, file resolution, space classification, layout planning, shell script generation), tested with `node --test` and no dependencies. Long-running work happens in Herdr terminals through small POSIX `sh` scripts in `mods/wool/bin/` (Herdr's `exec` has a 30 s limit), which record results in the worktree's private git dir (`<git-dir>/wool/`). `mods/wool/main.js` is thin glue: it watches `spaces()`/`panes()`, claims fresh worktrees, and turns plans into `run(...)` commands.

**Tech Stack:** Herdr app mod (gpui-kit JS, `herdr` module), Node 22 built-in test runner for logic tests, POSIX `sh`, git ≥ 2.36.

**Spec:** `docs/superpowers/specs/2026-11-04-wool-design.md` (read it before any task).

## Global Constraints

- Herdr docs and types are the truth: `~/.config/herdr-app/AGENTS.md`, `~/.config/herdr-app/herdr.d.ts`, `gpui-kit.d.ts`. Read-only; never edit shipped mods/layouts.
- Files under `mods/wool/lib/` import nothing from `herdr` or `gpui-kit` (so Node can test them). Only `main.js` imports those.
- No npm dependencies at run time or test time. Root `package.json` has `"type": "module"` and `"test": "node --test tests/"`.
- Config files: `.herdr/worktrees.yml.dist` / `.herdr/worktrees.yml` (setup, herdr-dog schema) and `.herdr/workspace.yml.dist` / `.herdr/workspace.yml` (layout, razajamil vocabulary). A `.yml` replaces its `.dist` entirely.
- Setup step env: `HERDR_WORKTREE`, `HERDR_MAIN_WORKTREE`, `HERDR_BRANCH`. Each step runs as `/bin/sh -c <run>` in the new worktree; first failure stops setup.
- Per-worktree state lives in `<git-dir>/wool/` (`git rev-parse --git-dir` of the worktree), never in the working tree.
- Never close, reorder or add agents to a space that did not arrive as a single plain shell; such spaces only get an added, unfocused "Setup" tab.
- Remote spaces (`space.machine !== null`) are skipped silently in v1.
- `herdr-app check mods/wool` must pass after every task that touches `mods/wool/`.
- Commits: conventional style (`feat:`, `test:`, `docs:`, `chore:`), ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Paths and branch names with spaces, quotes, `$` or slashes** (`~/Library/Application Support/…`, branch `feat/it's-$x`): every generated script and argv must still run the right command in the right folder. Pinned in Task 5 (`shellQuote` round-trip test running real `sh`).
2. **Setup terminal closed or Herdr quit mid-setup:** status must end as `failed`, waiting commands must not wait forever, and nothing re-runs on next start. Pinned in Task 5 (runner killed with SIGHUP → status `failed`; waiter exits on `failed`).
3. **Config files with CRLF line endings, a BOM, tab indentation, or comments after values:** CRLF/BOM/comments parse; tab indentation is rejected with the line number. Pinned in Task 2.
4. **A new space shows up before its first terminal is reported:** wool must wait, not classify it as "other" and skip the layout. Pinned in Task 6 (`classifySpace` returns `"pending"`; becomes `"other"` only after `PENDING_LIMIT_MS`).
5. **Two Herdr windows (two wool copies) or a hot reload during setup:** setup runs exactly once. Pinned in Task 6 (`wool-claim.sh` called twice → second reports `taken`).

### Task 5: Shell runner scripts

Setup runs in a terminal, not `exec` (30 s limit). These scripts are the only code that runs long.

**Files:**
- Create: `mods/wool/lib/shell.js`, `mods/wool/bin/wool-run.sh`, `mods/wool/bin/wool-wait.sh`, `mods/wool/bin/wool-bg.sh`
- Test: `tests/shell.test.js` (uses `node:child_process` to run real `sh` in `fs.mkdtemp` dirs)

**Interfaces:**
- Produces:
  - `shellQuote(s: string): string` — single-quote quoting safe for any string.
  - `setupScript(steps, env: { HERDR_WORKTREE, HERDR_MAIN_WORKTREE, HERDR_BRANCH }): string` — a POSIX script that `cd`s to `HERDR_WORKTREE`, exports the three vars, then for each step prints `==> <name or run>`, runs it via `/bin/sh -c` with that step's env, and on nonzero exit prints `wool: step '<label>' failed (exit N)` and exits with that code. Written by `main.js` to `<git-dir>/wool/setup.sh`.
  - `bin/wool-run.sh <stateDir> [-- cmd...]`: sets `<stateDir>/status` to `running`, runs `sh <stateDir>/setup.sh`; on success writes `ok`, else `failed <label>`; a `trap` on EXIT/HUP/INT/TERM writes `failed interrupted` if status is still `running`. On `ok` and a command given: `exec "$@"`. On failure: prints the failure and leaves the shell (the terminal stays open, Herdr keeps the shell).
  - `bin/wool-wait.sh <stateDir> -- cmd...`: prints `wool: waiting for setup…`, polls `<stateDir>/status` once a second; `ok` → `exec "$@"`; `failed …` → prints `wool: setup failed, not starting: <cmd>` and exits 1; missing status file for more than 10 s → treats as failed.
  - `bin/wool-bg.sh <stateDir> <n> [--wait] -- cmd...`: optionally waits like `wool-wait.sh`, runs the command with output to `<stateDir>/bg-<n>.log`, writes its exit code to `<stateDir>/bg-<n>.exit`.
  - `runArgv(binDir, stateDir, command: string | null): string[]`, `waitArgv(binDir, stateDir, command: string): string[]`, `bgArgv(binDir, stateDir, n: number, wait: boolean, command: string): string[]` — argv arrays for Herdr (`["sh", "<binDir>/wool-run.sh", stateDir, "--", "sh", "-c", command]`, etc.). Pane `env` is applied by prefixing `env K=V` (already quoted) — `withEnv(argv: string[], env: Record<string,string>): string[]`.

### Task 6: Detecting fresh worktree spaces and claiming them

**Interfaces:**
- Produces:

  - `isPlainShellArgv(argv: string[] | null | undefined): boolean` — true when `argv` has at least one entry and every entry after `argv[0]` is a flag (`/^-[A-Za-z]+$/`) without `c` (`["/bin/zsh","-l"]` → true; Herdr's `["/bin/zsh","-lic",…]` wrapper → false). *(Changed after Task 1: `program` can't tell a plain shell from a briefed agent; argv can.)*

### Task 7: Layout planning

**Files:**
- Create: `mods/wool/lib/plan.js`
- Test: `tests/plan.test.js`

**Interfaces:**
- Consumes: `Workspace`/`Pane` (Task 3); `runArgv`, `waitArgv`, `bgArgv`, `withEnv` (Task 5).
- Produces:
  - `type Ctx = { binDir: string, stateDir: string, agentArgv: string[] | null, shell: string }` (`shell`: the plain shell's `argv[0]`, e.g. `/bin/zsh`)

  - `planLayout(ws: Workspace, hasSetup: boolean, ctx: Ctx): { steps: Step[], warnings: string[] }` for a **plain-shell** space with a workspace file, where
    `Step = { op: "tab", ref: string, name: string | null, argv: string[] | null, task: string | null } | { op: "split", ref: string, from: string, direction: "right" | "down", argv: string[] | null } | { op: "closeOriginal" } | { op: "focus", ref: string } | { op: "background", argv: string[] }`.

All wrapped with `withEnv(argv, {...ws.env, ...pane.env})` when env is non-empty; a `split` step's non-null argv is then wrapped with `keepShell(argv, ctx.shell)` (tab steps are not). When `hasSetup` and no pane has `setup: true`, append a `Setup` tab. `waitForSetup` with `!hasSetup` runs the command directly. `closeOriginal` comes after all tabs are created; `focus` last: the `focus: true` pane, else first agent pane, else first pane.
  - `agentArgv === null` (no installed agent) makes agent panes plain shells and adds a warning (`No installed agent found; the Agent tab is a plain shell.`).
